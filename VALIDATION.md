# Validation Summary

v0.1.7 remote deployment validation: a second Windows host passed all 54 Node tests, the real-backend/bridge/panel YOLO smoke test, Appshots transport smoke, and the isolated native restart/token fixture. The panel update preserved official auth-file hashes and the backend binary; the production backend PID was unchanged. The default Administrator shortcut and persisted YOLO preference were verified from a separate SSH connection. Loading the new bridge in the production Desktop still requires one normal restart. Test temporary directories must sit outside the source package tree so extensionless CommonJS fixtures do not inherit its `type: module` setting.

YOLO panel control (unreleased, 2026-10-15): 54 Node tests passed, including authenticated permission writes, persistent defaults, stale-version rejection and managed-policy refusal. The real v8 backend behind the bridge confirmed full-access/never defaults and executed a write outside the fixture workspace. After a mode change and a new turn, it reported workspaceWrite/on-request; a fork followed the setting and returned to full access on its next turn without a backend restart. Three synthetic local Responses requests were used, with no real model calls or credentials. Edge desktop/mobile QA verified toggle persistence, existing account controls and no layout overflow. Native loaded-thread resume retains its earlier settings until a new turn; the UI explicitly describes next-turn semantics. Production Desktop is not restarted automatically during deployment.

Appshots and optional administrator launcher (unreleased, 2026-10-15):

- All 51 existing Node tests passed. Native launcher rebuilt with Rust 1.95.0; PowerShell token inspection matched the current process privilege and treated unavailable PIDs as unknown. Shortcut generation selected the explicit `--admin --restart` entry.
- The actual v8 backend behind the real bridge accepted inline PNG and local-image inputs. A synthetic local Responses service received the image and window text under identity A, retained both after identity B and a cold resume, and received a subsequent local screenshot. No real screenshot or credentials were transmitted. Native capture/menu clicking and real-account screenshot inference were not tested.
- Isolated normal and UAC-elevated restart fixtures stopped/reopened their desktop/backend processes, retained unrelated auxiliary processes and verified normal vs administrator backend tokens. The elevated run recorded both `launcherElevated=true` and `backendElevated=true`. These fixtures did not restart the production Desktop or prove elevation of every native computer-use helper.
- Appshots capture and feature availability remain owned by the installed Desktop and its organization policy. No ASAR edits or feature-gate overrides are installed.

Baseline: Windows Desktop `26.1007.2314.0`, original CLI `0.162.0-alpha.17.2`, Rust `1.95.0`, upstream commit `0c7362d121d1c7f69540262425fd4e2209fd8e8d`.

The following checks were performed during development. Raw real-account reports remain private because they include machine, identity and chat metadata. These are historical checks on the stated baseline, not guarantees for newer Desktop builds.

Version-alignment requirements are recorded in [VERSION-COMPATIBILITY.md](VERSION-COMPATIBILITY.md). Local/remote isolated performance measurements and scope limits are in [PERFORMANCE.md](PERFORMANCE.md); they distinguish the bridge's overhead from the unoptimized source build and exclude real model inference from shell/RPC timing.

The v0.1.2 performance follow-up repeated real A -> API -> distinct B -> A routing successfully and measured 2.81-4.91 second switches. A catalog-only concurrency test confirmed an unrelated chat's rename could wait 3.62-4.24 seconds on the shared state permit. This historical result motivated v0.1.3.

v0.1.3 validation: 45 Rust thread-manager tests plus the official-account fencing test passed. Local/remote isolated performance harnesses, legacy native routing and bridged paginated fork/history/cold-resume tests passed. A clean four-patch replay, already-applied detection, and preservation of the real Git index on overlapping/failing fixture patches passed. Real two-account catalog concurrency measured a 42.5 ms cached return and 18.9 ms maximum sibling rename latency during the cold switch. Real A -> API -> distinct B -> A routing and actual Get-Location/code-mode-host execution passed with gpt-5.6-luna; the earlier gpt-6-luna capacity rejection was recorded as a failure. Browser QA covered row reuse, metadata update/filtering, identity grouping/removal and desktop/mobile layouts. Detailed measurements and remaining contention limits are in PERFORMANCE.md.

The final Node suite passed 42 tests, including lifecycle retries, catalog return before helper teardown, overlapping patch/index preservation, and closure of descendant-retained pipes.

v0.1.4 official-usage validation: 49 Node tests passed, including distinct-account token routing, alias deduplication, account/user mismatch fencing, in-flight token rotation, cache/refresh throttling, bounded concurrency, error backoff/stale values and authenticated nonblocking quota reads. Synthetic Edge desktop/mobile QA verified quota bars, Credits balance, existing grouping/removal/row reuse and no identity text/button overlap. Read-only real queries returned separate quota and Credits data for both registered official accounts on both Windows hosts; original auth-file hashes stayed unchanged. No inference, login switching or reset-credit redemption was performed. This feature only changes the panel; the v0.1.3 Rust backend and installed-client version policy are retained.

v0.1.5 reauthorization validation: the official-login suite passed 51 tests, including matching-profile replacement, account mismatch refusal, staging cleanup and unchanged host auth. Private profiles continue to rely on the native persisted refresh-token path; the panel does not run a competing periodic refresh loop. Browser QA includes the per-account re-login control. A real re-login was not performed during automated validation because it requires a new device authorization by the account owner.

v0.1.6 side-chat validation: the optimized candidate backend passed legacy and paginated identity routing smoke tests, plus a compiled-backend side-chat test. The test created root identity A, forked a side chat, switched the root to B, resumed the side chat and verified its actual request Authorization used B. The side chat binding was updated to B; active-descendant waiting behavior is enforced by the backend. Existing installed v7 binaries were not changed during this candidate validation.
